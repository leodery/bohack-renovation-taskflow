# 和光里全屋通铺｜四分钟演示案例

合成案例。日期在新建演示项目时按当天生成。以下金额与收益都用于演示。

## 0:00–0:45 从原约定讲到变更

打开演示链接，直接进入中介视角。指向页面上方的原装修约定和住户变更。

**开场文案**：“这户老房原来定的是客厅、卧室分区铺砖，用 600×600 的砖，门口用扣条。现在业主想改做法，但到货、班组和交付时间都牵在一起。”

**住户原话**：“客厅和卧室的砖能不能连着铺？我想改成全屋通铺，换 800×800 的砖，门口别用原来的扣条。会多花多少钱？原来约好的交付日还能赶上吗？”

新增设计图为 D02。设计师确认起铺方向与同色石材过渡。施工团队确认材料、班组和工期。住户确认合成案例里的增项 1,500 元与交付安排。

## 0:45–1:45 为什么现场会擅自调序

**口播**：“原计划先查材料、复核基层，再铺砖，顺序本来没问题。问题是现场一变，必须马上决定的人和有权决定的人分开了。施工队知道现场能不能做，也承担当天窝工；设计师管做法，项目经理管班组顺序，业主决定能不能接受费用和交付的变化。班组已经到场，挨个问一圈，可能一天就过去了。于是现场容易凭经验先干，临时跳过一个节点。等后面发现问题，业主多花钱，施工队白做一遍，项目经理也得重新协调，利润被返工吃掉。”

切到「变更协商」，在版本记录上方点「切到住户，生成变更单」。输入：“班组已经到场，基层今天来不及复核，能不能先铺客厅？如果不能，哪些工作能先做，会不会多花钱？”提交后，系统保留原话并生成待确认的新单。切回中介，用变更下拉菜单选回预置案例，再在「工期与排程」点「检查错排草案」。

**口播**：“看起来是往前挪了一格，其实材料还没核对完、基层还没复核完，同一个班组当日还被排了两项工作。”

展示冲突列表和受影响的负责人。页面有冲突时无法提交各方确认。

## 1:45–2:45 展示可行方案

对比当前正式计划、错排草案和候选排程。新建默认案例里，候选保留材料核对和基层复核，复核结束后再铺贴。预计交付比当前计划提前 1 天，少 1 个班组空档日。

**口播**：“不取消复核，也能把空出来的一天用上。示例里按每个班组空档日 450 元计算，这一项估算少 450 元。”

## 2:45–4:00 说清谁拍板

点「采用候选排程」，提交调整原因：“将可执行的铺贴安排到前置完成后的最早日期，保留材料和基层复核。”

路演时可只现场切换一个身份，展示意见入口。其他身份如需提前确认，请在另一份排练案例预先完成。没有三方确认时，指着禁用的发布按钮说明约束即可。

**收尾文案**：“我们的目标是让工期安排更有效，少来回沟通，出了变化能立刻知道影响谁、谁该确认。正式工期只在设计、施工和住户确认后由中介更新。”

**被问到照片时**：施工后仍由人审核。比如照片标签写 600×600，而 D02 确认的是 800×800，AI 只把疑点和原图交给审核人，由审核人决定是否退回。

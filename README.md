# 工序共识 · 家装四方协作平台

住户提出装修变更，设计师补齐图纸，施工团队核对材料与工期，中介方组织分工。各方确认同一版本后，系统才发布正式排期和执行任务。退回原因、版本修订、任务交付和住户验收均保留记录。

当前可运行版本围绕「分区铺砖改为全屋通铺」完成一条完整协作流程。它使用真正的账号、项目成员权限和服务器数据库；手机和电脑访问同一台服务器即可共享记录。

## 五分钟启动

需要 Python 3.11 或更新版本，已在 Windows / Python 3.12 验证。首次安装依赖需要联网。

**Windows：双击 `start.cmd`。** 出现启动提示后打开 [本机平台](http://localhost:8765)。启动窗口保持运行；关闭窗口后服务停止。

或在仓库目录执行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe server.py
```

macOS / Linux：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py
```

服务默认监听 `0.0.0.0:8765`。其他设备连接同一局域网，打开 `http://服务器的局域网IP:8765`。这台机器的地址可用 `ipconfig` 查看；地址会随网络变化。**四个人要访问同一地址，不要每人启动一份独立数据库。** 若不能连接，检查设备网络和服务器的入站端口配置。

邀请链接沿用当前访问地址。准备邀请手机用户时，请先用局域网地址打开平台，再生成邀请；`localhost` 链接只指向打开它的设备本身。当前仓库没有公网部署地址。

## 四个人第一次如何配合

| 身份 | 操作 | 完成的标志 |
|---|---|---|
| 中介方 / 产品总监 | 注册，创建项目，填写原方案说明和图纸版本；在「成员与邀请」生成其他三种身份的邀请码 | 三位队友出现在项目成员中 |
| 住户 | 注册为住户，使用对应邀请码加入；进入「变更协商」提交原话 | 生成带原文依据、待确认事项和候选任务的协商草案 |
| 设计师 | 补齐规格、铺法、起铺点、收边和图纸版本，填写修订原因；再上传图纸 | 图纸上传时填写的版本，与方案字段一致 |
| 施工团队 | 补齐施工做法、供应商、报价范围、编号、金额、有效期、到货日、班组日期和工期；再上传报价 | 报价文件的编号与方案字段一致，报价仍有效 |
| 中介方 / 产品总监 | 指定每项确认的具体人员；调整任务名称、交付物、执行人、一个或多个确认人、截止日和方案 | 每项任务都分派到已加入项目的账号 |
| 设计师 → 施工团队 → 住户 | 依次确认当前版本，或填写原因退回 | 三项确认都通过 |
| 中介方 / 产品总监 | 点击「发布正式任务与排期」 | 正式施工方案更新，执行任务生成 |
| 施工团队与任务确认人 | 上传现场记录，按依赖顺序提交任务；指定确认人逐一确认或退回 | 全部任务确认完成，进入最终验收 |
| 住户 | 填写人工验收意见，通过或退回整改 | 验收通过后关闭本次变更 |

每个邀请码只能使用一次，三天内有效，账号身份须与邀请码一致。平台没有预置公共密码。注册后，账号角色暂不支持修改；同一身份可以有多位成员，确认和分工绑定到具体账号。

## 已实现的规则

- **确认之前不更新正式任务。** 草案修改仅形成新协商版本；三项确认完成后，由中介方发布时统一更新排期和任务。
- **修订后重新确认。** 改图纸、报价、人员或日期都会生成新版本；旧版确认保留在历史中，但不能充当新版确认。
- **退回必须有原因。** 设计/施工/住户确认、执行任务审核和最终验收都记录操作人、时间和意见。
- **任务有前置条件。** 到货与基层复核通过后才能提交铺贴任务；铺贴通过后才能提交自检。多位确认人必须全部通过。
- **缺信息就等待。** 没有确认的规格、价格和日期留空，不用 AI 编造；缺少匹配的图纸/报价文件、报价过期或日期不合理时阻止发布。
- **多人同时编辑有保护。** 提交时检查共享版本；旧页面不能覆盖队友的新修改。页面每八秒检查更新，正在填写的表单不会被自动刷新覆盖。
- **账号权限由后端检查。** 非成员不能读取项目或附件；住户不能代替设计师确认，施工人员不能代替住户最终验收。
- **过程可查看和打印。** 「确认与退回记录」展示事件；协商页保留各版字段、责任分派、原始要求。点击「打印共享协议单」可通过浏览器保存 PDF。

## 工期计算与任务模板的范围

通用分工字段采用「任务、交付物、执行人、确认人、前置条件、截止日」。团队可用 [GB/T 37507-2025 项目管理指南](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=1A62CB6675D7C79A483323B77305F776) 查阅通用项目管理参考，并用 [JGJ/T 304-2013 发布公告及附件](https://www.mohurd.gov.cn/gongkai/zc/wjk/art/2015/art_17339_224535.html) 核对住宅装修验收依据。实际验收要求由团队按项目和适用标准确认。

当前使用可解释的铺砖任务模板：到货核对、基层复核、按图铺贴、自检交付。设计与报价作为前置协商和确认事项。任务名称、交付物、人员与日期可修改，依赖关系保持样板约束。

这份模板是产品样例，不是国家工程分工标准，也尚不能可靠拆分任意装修大工程。新的施工类型需要增加相应模板、必要资料和确认规则。

系统比较两种条件方案：

1. 直接顺延：开始日取材料到货日与班组最早开工日的较晚者；交付日按施工方填写的总日历天数计算。
2. 先做可并行工作：施工方填写具体可并行内容与可追回天数后，计算缩短后的交付日。

日期包含开始当天，按日历天计算，暂不计算节假日、班组资源冲突和逐道工序时长。可追回天数由施工方提供并由相关人员确认，不能把这个结果当作已证明的最优工期。

供应商暂作为报价来源记录，由施工团队或中介方上传资料；登录主体保持住户、中介方、设计师、施工团队四类。

## AI 与资料核对

不配置模型时，平台会明确显示「规则模板草案 · 未调用模型」，仍可完成整个协作流程。规则先识别原话中的目标铺法及规格，责任草案使用固定样板，最终均由人确认。

可选接入兼容 Chat Completions、支持 JSON 输出的模型。服务器启动前，在同一个终端设置：

```powershell
$env:TASKFLOW_MODEL_URL = '你的完整 chat/completions 接口地址'
$env:TASKFLOW_MODEL_NAME = '服务商提供的模型名称'
$env:TASKFLOW_MODEL_KEY = '你的密钥'
.venv\Scripts\python.exe server.py
```

接口地址需要包含完整路径。密钥只在服务器环境变量中使用，不进入浏览器或仓库；本项目不会自动读取 `.env`。配置模型后，提交的变更原话、核对资料的文字和对应字段会发送至你配置的服务商。

- 模型用于提取原文事实、提出澄清问题，以及辅助核对资料文字；不能审批、发布任务或判定验收通过。
- 事实必须带能在原话中找到的证据片段；模型无法调用或返回异常时，会明确提示退回规则处理。
- 「核对资料清单与文字」检查当前图纸、报价和施工记录是否齐备。当前仅直接读取 UTF-8 TXT，每次最多 12 份资料、每份前 6000 字；PDF、图片和 DOCX 可上传留存，但内容需人工查看。
- 规则核对能提示 `图纸版本：D01`、`报价单编号：Q01` 这样的显式编号与当前字段不一致。模型产生的冲突提示也必须带对应文件的原文片段。
- 核对报告记录版本和时间。资料齐备或没有发现冲突，都不会改变审批或验收状态。

**验证状态：未配置真实模型密钥进行在线调用；已测试接口不可用时的明确降级，以及模型返回无原文依据事实时的过滤。**

## 数据与部署

技术栈：Flask + SQLite + Waitress，前端为 HTML/CSS/JavaScript，无需 Node 构建。SQLite 事务保存共享状态和附件，密码存储哈希，登录会话使用 HttpOnly Cookie，写操作校验 CSRF 与项目版本。

用户、项目、会话与附件保存在 `instance/taskflow.sqlite3`，该目录已被 Git 忽略。备份应在停止服务后复制整个 `instance` 目录，避免遗漏 SQLite 的附属文件。不要把测试数据、密码或模型密钥提交到仓库。

| 环境变量 | 用途 | 默认值 |
|---|---|---|
| `TASKFLOW_HOST` | 监听地址 | `0.0.0.0` |
| `TASKFLOW_PORT` | 服务端口 | `8765` |
| `TASKFLOW_DATA_DIR` | 数据目录 | 仓库内 `instance` |
| `TASKFLOW_SECURE_COOKIE` | HTTPS 部署时设为 `1` | 未设置 |
| `TASKFLOW_MODEL_URL` / `TASKFLOW_MODEL_NAME` / `TASKFLOW_MODEL_KEY` | 可选模型配置 | 未设置，使用规则模式 |

本版适用于黑客松和小团队试用。尚未提供找回密码、账户管理后台、项目成员移除、推送通知或公网部署脚本。公网部署需配置 HTTPS 和可信代理的转发设置；不要直接照搬局域网 HTTP 地址作为公网产品入口。

## 验证与文件入口

运行自动检查：

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

覆盖四方完整闭环、越权/CSRF、旧版本冲突、报价过期、退回后重新确认、多确认人、资料缺项和原文依据。另已用四个独立浏览器会话验证注册、邀请码加入、退回修订、共同确认、执行和最终验收，并检查 390 像素手机布局与打印内容。浏览器验证使用合成案例；这不等同于真实施工效果验证。

| 文件 | 职责 |
|---|---|
| `server.py` | 注册登录、项目成员、API、共享数据与私有附件 |
| `domain.py` | 角色权限、版本规则、确认顺序、任务依赖与验收 |
| `analysis_service.py` | 模型调用、原文证据过滤、规则降级与资料核对 |
| `static/` | 四方共用的响应式页面 |
| `tests/` | 可重复运行的业务与权限测试 |
| `prototype/task-breakdown.html` | 原有独立原型，保留作历史参考 |

赛前已有内容与比赛期间新增内容，可按 Git 提交时间和提交号如实登记；本仓库不会自动替团队提交赛事材料。
